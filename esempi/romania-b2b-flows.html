Romania — RO e-Factura
fatturazione elettronica B2B

Guida al sistema RO e-Factura, la piattaforma centralizzata dell'ANAF (Agenzia Nazionale per l'Amministrazione Fiscale) per la fatturazione elettronica B2B in Romania. Obbligo pieno per tutti i soggetti passivi dal 1° luglio 2026.

Normativa
Legea nr. 296/2023
O.U.G. nr. 120/2021
Mandato B2B
Dal 1° luglio 2024 (tutti)
Grazia PMI scaduta: 1° lug 2026
Termine invio: 5 giorni lavorativi

Quadro normativo

La Romania ha introdotto RO e-Factura con l'Ordonanța de urgență nr. 120/2021, inizialmente per il B2G. L'obbligo B2B è stato esteso con la Legea nr. 296/2023 (legge di bilancio 2024), che ha reso obbligatoria la trasmissione di tutte le fatture B2B tramite RO e-Factura a partire dal 1° gennaio 2024 (per grandi contribuenti) e dal 1° luglio 2024 per tutti i soggetti passivi. La Legea nr. 97/2024 ha successivamente chiarito le sanzioni e il regime transitorio per le PMI con fatturato inferiore a 500.000 EUR, con periodo di grazia scaduto il 1° luglio 2026.

Il sistema è gestito dall'ANAF (Agenzia Nazionale per l'Amministrazione Fiscale) attraverso il portale Spațiul Privat Virtual (SPV) e le relative API.

Modello centralizzato con validazione ANAF: ogni fattura B2B deve essere inviata all'ANAF entro 5 giorni lavorativi dalla data di emissione. L'ANAF valida la fattura, le assegna un identificativo univoco e la mette a disposizione del destinatario. Solo le fatture con validazione ANAF hanno valore fiscale e legale.

Scadenze progressive

1° luglio 2022
B2G obbligatorio — RO e-Factura verso Pubblica Amministrazione
Tutti i fornitori della PA rumena devono trasmettere le fatture tramite RO e-Factura. Esteso a tutti i livelli della PA (centrale e locale).
1° gennaio 2024
B2B obbligatorio — grandi contribuenti
I soggetti classificati come grandi contribuenti dall'ANAF devono inviare le fatture B2B tramite RO e-Factura. Periodo transitorio con sanzioni sospese per i primi mesi.
1° luglio 2024
B2B obbligatorio — tutti i soggetti passivi
L'obbligo si estende a tutti i soggetti passivi IVA registrati in Romania. Le PMI con fatturato inferiore a 500.000 EUR beneficiano di un periodo di grazia (senza sanzioni) fino al 1° luglio 2026.
1° luglio 2026
Fine periodo di grazia — obbligo pieno per tutti
Scade il periodo di tolleranza per le PMI con fatturato < 500.000 EUR. Dall'1° luglio 2026 l'obbligo è pieno e le sanzioni si applicano a tutti i soggetti passivi senza eccezioni.

Flusso di emissione tramite RO e-Factura

Registrazione e autenticazione allo SPV/API
L'emittente accede al sistema tramite il portale SPV (Spațiul Privat Virtual) con certificato digital qualificat (semnătură electronică), oppure tramite le API REST dell'ANAF autenticandosi con OAuth2 e certificato qualificato. I soggetti stranieri registrati IVA in Romania possono usare il token virtuale.
Generazione della fattura XML RO_CIUS
Il sistema ERP genera il file XML secondo il profilo RO_CIUS (CIUS — Core Invoice Usage Specification rumena), basato su UBL 2.1 o CII conforme alla norma EN 16931. I campi specifici rumeni includono: CIF (Codul de Identificare Fiscală) di emittente e destinatario, codice prodotto NC/CPV, CIF TVA per IVA intracomunitaria.
Invio all'ANAF entro 5 giorni lavorativi
La fattura deve essere inviata all'ANAF entro 5 giorni lavorativi dalla data di emissione (non dalla data di consegna al cliente). L'invio avviene tramite API (POST /FCTEL/rest/upload) o portale SPV. Il sistema accetta file XML singoli o archivi ZIP multipli.
Validazione ANAF e assegnazione ID
L'ANAF elabora la fattura entro pochi minuti (generalmente secondi). Se la validazione ha esito positivo, la fattura riceve un ID unic de identificare e viene firmata digitalmente dall'ANAF con sigillo elettronico qualificato. La fattura firmata ha valore legale.
Download della fattura firmata
L'emittente scarica il file XML firmato dall'ANAF tramite API (GET /FCTEL/rest/descarcare?id={id}). Questo file è il documento legalmente valido da inviare al cliente (non il file originale non firmato).
Messa a disposizione al destinatario
La fattura firmata è disponibile nell'area SPV del destinatario (accesso tramite CIF). Il destinatario deve scaricarla entro 60 giorni dal caricamento; dopo tale termine la fattura rimane archiviata dall'ANAF ma esce dalla coda attiva dello SPV.
Conservazione
L'ANAF conserva le fatture per 10 anni. I soggetti passivi devono comunque conservare copia delle fatture nei propri archivi aziendali secondo le norme contabili rumene (Legea contabilității nr. 82/1991).

Stati della fattura in RO e-Factura

Codice statoSignificato
în prelucrareIn elaborazione: l'ANAF sta validando la fattura inviata.
XML cu erori nepreluat de sistemRifiutata: il file XML contiene errori di schema o di business. L'emittente riceve un file di errore con la lista dei problemi da correggere.
OKValidata: la fattura è stata accettata dall'ANAF, firmata e resa disponibile al destinatario. L'ID univoco è stato assegnato.
StornatăStornata: la fattura è stata parzialmente o totalmente annullata tramite nota di storno (stornare) o fattura correttiva.

Scenari operativi

Scenario 1 — Emissione standard (API REST)

  1. L'ERP genera il file XML RO_CIUS e lo invia all'API ANAF (POST /FCTEL/rest/upload?cif={CIF_emittente}&tip=FACT1).
  2. L'ANAF risponde con un index de incarcare (numero di caricamento) per il tracking.
  3. L'ERP interroga lo stato (GET /FCTEL/rest/stareMesaj?id_incarcare={id}) finché non ottiene risposta OK.
  4. L'ERP scarica il file XML firmato ANAF (GET /FCTEL/rest/descarcare?id={id}) e lo archivia.
  5. L'ERP invia il file firmato al cliente via email o portale (facoltativo: il cliente può scaricarlo autonomamente dallo SPV).

Scenario 2 — Fattura con errori (ciclo di correzione)

  1. L'ANAF restituisce stato XML cu erori con un file ZIP contenente il messaggio di errore in XML.
  2. L'ERP analizza il file di errore (codici errore ANAF: schema, regola business, dati fiscali mancanti).
  3. L'operatore corregge la fattura nel gestionale e la reinvia come nuovo caricamento.
  4. La fattura originale errata non riceve ID ANAF e non ha valore fiscale; non occorre emetterne una stornata.

Scenario 3 — Fattura correttiva (stornare parziale o totale)

  1. Il destinatario segnala un errore sulla fattura già validata dall'ANAF.
  2. L'emittente genera una fattura correttiva XML RO_CIUS di tipo 380 (credito) che richiama l'ID ANAF della fattura originale.
  3. La fattura correttiva viene inviata all'ANAF tramite API e convalidata come documento separato con proprio ID.
  4. Se necessario, l'emittente emette una nuova fattura corretta.
  5. Entrambe (originale + correttiva) sono visibili nel registro ANAF e nello SPV del destinatario.

Scenario 4 — Soggetti non stabiliti in Romania (non-residenti)

  1. I soggetti non stabiliti ma registrati IVA in Romania per operazioni soggette a obbligo di e-invoicing devono usare RO e-Factura.
  2. L'autenticazione alle API ANAF richiede un certificato qualificato o la delega a un rappresentante fiscale stabilito in Romania.
  3. I soggetti non registrati IVA in Romania (acquisti in reverse charge) non devono caricare fatture su RO e-Factura.

Casi speciali ed esclusioni

  • Fatture B2C: escluse dall'obbligo RO e-Factura. Le vendite ai consumatori finali seguono le regole ordinarie (bon fiscal / factură simplificată).
  • Operazioni intracomunitarie (ICS/IAC): le cessioni e gli acquisti intracomunitari non transitano per RO e-Factura; sono soggette alle regole IVA ordinarie e al sistema VIES.
  • Esportazioni: escluse da RO e-Factura.
  • Operazioni esenti IVA (art. 292 Codul Fiscal): alcune categorie di operazioni esenti sono escluse dall'obbligo (da verificare caso per caso).
  • Factură simplificată: le fatture semplificate (importo ≤ 100 EUR o operazioni specifiche) sono soggette all'obbligo RO e-Factura se emesse tra soggetti passivi.
  • Sanzioni: la mancata trasmissione o la trasmissione oltre i 5 giorni è sanzionata con ammende da 1.000 a 10.000 RON per persona giuridica (5.000–10.000 RON per grandi contribuenti).
